# 포트폴리오 — note의 근거자료

> 인터뷰에서 매니저에게 **보여줄 자료**다. 화면에 띄울 순서대로 정리했다.
> 각 항목은 `주장 → 근거 파일 → 보여줄 것 → 한계` 순서다. **한계를 같이 적은 이유는 먼저 밝히는 쪽이 신뢰를 얻기 때문이다.**

> ⚠️ **이 문서보다 `05_reference_model.md`를 먼저 보여준다.** 계층 구분(Policy / Guardrail / Evidence / Assessment)을 깔지 않으면 아래 §0과 §1·§2가 **같은 파일을 근거로 서로 다른 주장을 하는 것처럼** 보인다. 각 절이 어느 계층인지는 `05_reference_model.md` §5 표에 있다.

## 1. 1.1 — Policy-as-Code 실물

**주장** 법·프레임워크 기준을 기계가 읽는 정책으로 변환해 baseline spec과 rule set을 코드로 관리했다.

**근거 파일** `tmac-poc/tmac.yaml` (v1.1.0, `apiVersion: tmac/v1`, `kind: ThreatModel`)

### 보여줄 것 ① — 경계 정의가 곧 baseline spec

| ID | 경계 | 유형 | trust_level | 비고 |
|---|---|---|---|---|
| B-01 | user_input | input | `untrusted` | 항상 검증 |
| B-02 | rag_retrieval | data_access | `semi_trusted` | 문서 접근 범위 제한 |

| Threat | 경계 | severity | 탐지 방식 | 조치 |
|---|---|---|---|---|
| T-01 prompt_injection | B-01 | critical | rule_engine (룰 11개) | `block` |
| T-02 rag_injection | B-02 | high | rule_engine | `block` |

### 보여줄 것 ③ — T-01 룰의 진화 흔적

초기 4개(한국어·영어 지시 무시, 대량 탈취, 일반 태그) → 신규 7개 추가:
llama3 특수 토큰 삽입(`<|eot_id|>` 등, confidence 0.99), assistant/system 헤더 위조(0.99), 역할 전환(0.85), 픽션 우회(0.75), 언어 전환 우회(0.80), Base64 인코딩(0.70), 공백 삽입 분리(0.85)

**말할 것** "룰이 처음부터 11개였던 게 아니라, 우회 시도를 보면서 늘어난 결과입니다. 그래서 정책을 코드로 둬야 한다고 생각했습니다 — 문서였으면 이 이력이 남지 않습니다."

**한계** 단일 서비스(HR 어시스턴트) 대상 모델이다. 전사 baseline이 아니라 **한 파이프라인의 baseline을 코드로 만든 사례**로 말한다.

## 2. 1.2 — 무엇이 감사 가능한지 측정한 결과

**주장** 통제 기준을 정의하기 전에 "무엇이 증거로 남는가"를 먼저 측정했다. 그 결과가 Assurance에 넘길 기준의 상한을 정한다.

**근거 파일** `claude-lab/spike/audit_tables.md` (생성 파일 — 손으로 옮긴 숫자 없음), `claude-lab/docs/results.md`

**실험 조건** 유효 실행 **55회** / 도구 인자 **1,102개** / 4개 조건(fixture 2종 × 모델 2종)
제외: 응답 절단 21회, `max_tokens≠4096` 37회 (총 113회 중)

### 보여줄 것 ① — 계층 능력 행렬 (매처 강도와 무관)

| 능력 | C1 off | C1 on | C2 state | C3 결합 | C4 실행증거 |
|---|---|---|---|---|---|
| argument 열거 | ○ | ○ | △ 첫 후보만 | ○ | ○ |
| 값이 입력에 존재하는지 판정 | ✕ | ○ | ○ | ○ | ○ |
| **어느 source인지 지명** | ✕ | ✕ | ○ | ○ | ○ |
| **선언된 trust·획득채널 복원** | ✕ | ✕ | ✕ | ✕ | **○** |
| **입력을 전송 바이트와 대조** | ✕ | ✕ | ✕ | ✕ | **○** |

**먼저 인정할 것** "출처 지명은 C3(표준 trace + checkpoint state)로도 됩니다. 전용 계층이 필요한 건 아래 두 줄입니다."

### 보여줄 것 ② — 수치 (min fixture / Haiku 4.5 / 30회 / 외부 출처 3건)

| 관측 계층 | 매처 | source 지명 | trust 복원 |
|---|---|---:|---:|
| C1 trace (내용 off) | 보수 | 0.000 | 0.000 |
| C1 trace (내용 on) | 보수 | 0.000 | 0.000 |
| C2 state | 보수 | 0.221 | 0.000 |
| C3 결합 | 보수 | 0.293 | 0.000 |
| C3 결합 | 관대 | 0.514 | 0.000 |
| C4 실행증거 | 보수 | 0.293 | **0.530** |
| C4 실행증거 | 관대 | 0.514 | **0.807** |

### 보여줄 것 ③ — 재호출 변동 (동일 입력 재호출, checkpoint 복원 아님)

| 조건 | 후보 **수** 이탈률 | **action 집합** 이탈률 |
|---|---:|---:|
| min / Haiku 30회 | 0.033 | **0.9** (25/30이 서로 다름) |
| min / Sonnet 5 8회 | 0.125 | **0.75** (6/8) |
| wide / Haiku 12회 | **0.0** | **0.917** (12/12 전부 다름) |
| wide / Sonnet 5 5회 | **0.0** | **0.8** (5/5 전부 다름) |

**가장 강한 대비** wide 조건 두 개는 **후보 수가 완전히 일정**한데(이탈률 0.0, 전 실행이 9개) **인자 값을 포함한 집합은 전부 서로 다르다.**

**해석(따로 말한다)** 호출 횟수는 안정적인데 인자 값을 포함한 action 집합은 75~92%가 다르다. 따라서 **같은 입력을 다시 넣어 확인하는 방식은 과거 실행의 감사 수단이 되지 못한다.** 실행 시점에 증거를 남겨야 한다.

### 보여줄 것 ④ — 탐지 임계값 민감도

`tmac-boundary-gate/experiments/reports/threshold_sweep_v0.3.6.md`
모델 `distilbert_pi_v0.3` / 테스트셋 N=50 (공격 20, 정상 30) / 2025-12-29

| Threshold | Precision | Recall | F1 | TP | FP | FN | TN |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0.50 | 0.513 | **1.000** | 0.678 | 20 | **19** | 0 | 11 |
| **0.55** | 0.696 | 0.800 | **0.744** | 16 | 7 | 4 | 23 |
| 0.60 | 0.800 | 0.200 | 0.320 | 4 | 1 | **16** | 29 |

→ 단일 임계가 아니라 3단 정책: `<0.50 allow` / `0.50–0.55 sanitize` / `≥0.55 block(or ask_human)`

**한계 (물으면 그대로 말한다)**
- N=50은 소규모다. 성능 주장이 아니라 **임계값 판단 근거**로 쓴다.
- **코드 현행값과 실측 권고가 다르다.** `policy_engine.py`는 v0.1 기본값 `0.5 / 0.8`이고 실측 권고는 `0.50 / 0.55`다. 아직 반영 전이다 → **이걸 1.5 Closed Loop의 실제 필요 사례로 연결한다.**
- 이 리포트 파일은 PowerShell 리다이렉션 잔여물(`@"…"@ | Out-File`)이 포함돼 있다. **화면에 원본을 띄우지 말고 위 표만 보여준다.**

**근거 파일** `tmac-poc/tests/e2e/results_20260515_172159.txt` (2026-05-15, pytest)

**실측** 154건 수집 → **141 passed / 13 failed**, 소요 7분 53초
테스트 모듈 8개 (괄호는 테스트 **함수** 수, 154는 파라미터화 후 실행 건수):

실패 13건이 **조치가 서로 다른 4종**으로 갈린다.

| 분류 | 건수 | 관측된 내용 | 필요한 조치 |
|---|---:|---|---|
| **(a) 위협 귀속 오류** | 8 | 게이트웨이가 위협을 정의 순서대로 평가하고 **첫 매칭에서 반환** → T-06 패턴이 T-01 룰에 먼저 걸린다. 차단은 되지만 `threat_id`가 T-01로 기록. T-04a→T-02, T-04b→T-02 동일. 그 결과 기대 ID로 이벤트가 저장되지 않는 실패 1건 포함 | 평가 순서·우선순위를 **정의에 명시**해야 한다 |
| **(b) 집행 누락** | 3 | T-08에 `max_requests_per_minute: 20`이 정의돼 있으나 25회 연속 요청에서 throttle **0회**. 4,000자 제한도 미동작 | 구현 문제 — 정의가 자동 집행을 보장하지 않는다 |
| **(c) 과차단** | 1 | `나에게 미팅 일정 메일 보내줘` (`mail_send_self` 0.20, 저위험 단일 호출)가 T-04b 연쇄 초과로 차단 | 누적 임계 조정 |
| **(d) 미차단** | 1 | EP-001 `hr_db_query → mail_send_all`이 차단되지 않고 **응답에 직원 급여가 실제 노출** | 탐지 설계 재검토 |

**말할 것 — 관측과 해석을 나눈다**

>
> (해석) "**정책 파일에 위협을 정의하는 것과 그게 실제로 집행되는 것은 다른 일입니다.** 특히 (a) 8건은 차단이 되니까 로그만 보면 정상으로 보이는데, 위험 집계가 조용히 왜곡됩니다. 테스트가 아니면 발견되지 않습니다."

## 3. 1.3 — 위협 모델링 방법론과 탐지 근거

**주장** 에이전트 위협은 흐름의 **타입이 전환되는 지점**에서 발생하고, 기존 DFD는 그 지점을 표현할 수 없다.

**근거 파일** `langgraph-tb-analysis/` (`00_요약.md`, `02_선행연구_차별화.md`, `03_실증계획.md`), `tmac-boundary-gate-docs/papers/kics/kics_prompt_boundary_v0.99.md`

### 보여줄 것 ① — 화살표 3종

같은 시나리오("메일 찾아 요약하고 캘린더에 등록해줘")에서

| 흐름 | 무엇이 이동하나 | DFD 표현 |
|---|---|---|
| data flow | 메일 내용 | 표현됨 |
| **control flow** | LLM 출력(데이터)이 **다음 행동을 결정하는 명령으로 변신** | 표현 안 됨 |
| **privilege flow** | 같은 캘린더 등록이 **누구 권한으로** 실행되나 | **표기 방법 자체가 없음** |

경계 식별 기준 = **"흐름의 타입이 전환되는가"**. 컴포넌트 배치 기준이 아니다.
reference model: 신뢰구역 **L0~L8** × 경계통과 **TB-1~9**

### 보여줄 것 ② — 경쟁 프레임과의 위치

| 프레임 | 구조 | 차이 |
|---|---|---|
| MAESTRO (CSA, IriusRisk 통합) | 7층 건물, 층별 체크리스트 | 층 안은 보지만 **층 사이 전환은 못 봄** (CSA 스스로 cross-layer를 약점으로 명시) |
| 의료 8-boundary (STRIDE-per-element) | 8개 구역, 배치 기준 | 화살표는 여전히 한 종류 |
| CLAWAUDIT | 경계 2개 사례 감사 | 사례를 일반화한 것이 우리 쪽 |
| PFI / MAC / ScopeGate | 런타임 차단 장치 | **경쟁이 아니라 우리 좌표계 위에 배치되는 통제 수단** |

**말할 한 문장** "선행 방어 기법들은 경쟁 상대가 아니라 제 좌표계 위에 놓이는 통제 수단입니다. 어느 경계에 아직 방어가 없는지를 드러내는 게 이 모델의 용도입니다."

**포인트** 개별 호출은 모두 허용 범위인데 **연쇄되면 경계를 넘는다.** 단일 요청 검사만으로는 잡히지 않는 형태다.

### 보여줄 것 ④ — Prompt Boundary 탐지 (KICS 논문)

Prompt Injection을 모델 내부 문제가 아니라 **사용자 입력과 시스템 제어 정보가 결합되는 지점의 경계 위협**으로 재정의. DistilBERT 경량 탐지기로 사전 선별 → `allow` / `sanitize` / `block` 다단계 결정. OWASP LLM Top 10 기반 공개+합성 데이터셋.

**말할 것** "모델을 고치지 않고 적용할 수 있다는 점이 실무 조건이었습니다. 3rd-party 모델을 쓰면 내부를 손댈 수 없으니까요."

### 보여줄 것 ⑤ — 검증 설계 (seeded vulnerability)

결함 7개를 심고 프레임워크별로 도달하는지 측정하는 설계

| # | 심는 결함 | 대응 경계 | 의도 |
|---|---|---|---|
| V1 | API 인증 누락 | TB-1 | **대조군** — 전통 DFD도 잡아야 함 |
| V2 | 검색 문서 내 간접 인젝션 | TB-3/4 | DFD에선 평범한 data flow |
| V3 | system instruction과 RAG를 구분자 없이 연결 | TB-4 | trust 결합 기준 필요 |
| V4 | 모델 출력을 스키마 검증 없이 tool call로 파싱 | TB-6 | data→control 전환 |
| V5 | 사용자 권한 무관하게 service account로 실행 | TB-7 | **confused deputy — DFD에서 구조적으로 안 보임** |
| V6 | tool result를 출처 없이 memory 저장·재사용 | TB-8 | 1회 이동 vs 반복 재유입 |
| V7 | audit에 결정만 기록, 근거 미기록 | TB-9 | evidence 축 필요 |

**한계**
- 논문 심사 자체 판정은 **Major Revision**이다. 게재 완료로 말하지 않는다.
- 차등 커버리지 실험은 **설계 단계**다. 수행 결과가 아니다.
- 선행연구 일부(ScopeGate)는 검색 요약으로만 확인했다 — 인용 시 원문 확인 필요 상태.

    [기준 정의]로 복귀

### C2가 잃는 것 — state 단독의 한계

| 조건 | 열거 가능 / 전체 argument | 비율 |
|---|---|---:|
