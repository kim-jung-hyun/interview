## 논문의 핵심 주장 (한 줄)

**"LLM 기반 Agentic System의 위협을 제대로 모델링하려면, 기존 DFD 기반 trust boundary(data flow 단일 축)로는 부족하며, control flow와 privilege flow를 별도 축으로 추가한 확장된 trust boundary 모델이 필요하다."**

- 기여 1: 실행 구조를 data/control/privilege flow로 분류, privilege flow가 독립 축임을 논증 (4.2)
- 기여 2: "flow의 전환"까지 식별 조건에 포함하는 Agentic Trust Boundary 확장 정의 + crossing 방향에 따른 위협 성격(오염 vs 노출) (4.3)
- 기여 3: trust zone(L0~L8)과 boundary crossing(TB-1~9) reference model + threat elicitation 프레임 (5장)

## 쉬운 설명 (비서 AI 예시)

"메일 찾아 요약하고 캘린더에 등록해줘" 요청을 처리하는 AI 비서에서:

- 기존 DFD: `메일함 → 에이전트 → LLM → 에이전트 → 캘린더` — **화살표 4개가 전부 같은 화살표** ("데이터 이동" 의미 하나뿐)
- 이 논문: 화살표에 3종류가 있다
  - **data flow**: 메일 내용이 이동 (기존 DFD가 잘 표현)
  - **control flow**: LLM 출력(데이터)이 "다음 행동"을 결정하는 **명령으로 변신**하는 지점 — 메일에 숨겨진 인젝션이 여기서 에이전트를 조종
  - **privilege flow**: 같은 캘린더 등록이라도 김대리 권한 vs 시스템 계정 권한에 따라 피해가 다름 — DFD에는 표시할 방법 자체가 없음

> 한 문장: 기존 설계도는 "데이터가 어디로 가는지"만 그리는데, AI 에이전트의 진짜 위험 지점은 **"데이터가 어디서 명령으로 변하는지"와 "그 명령이 누구 권한으로 실행되는지"**이고, 이 논문은 그 지점을 설계도에 그려 넣는 방법을 제안한다.

## 심사관 관점 최종 판정

**아이디어는 의미가 있으나, 현재 원고는 그 의미를 스스로 입증하지 못한 상태. → Major Revision**

| 투고처 | 현재 원고 | 보강 후 (관련연구+MAESTRO 포지셔닝+차등 실험) |
|---|---|---|
| 학술 학회 (top-tier) | Reject | 여전히 어려움 (novelty 폭 좁음) |
| 학술 학회 (mid-tier/워크숍) | Weak Reject ~ Major Revision | Accept 가능권 (워크숍 유력) |
| 산업 보안 컨퍼런스 (CFP) | Borderline | 통과 가능성 높음 |

### 살아남는 고유 기여 (좁지만 진짜)
1. **식별 기준의 형식화**: "crossing = flow 타입의 전환" 판정 기준 + Loop Controller 반례 처리 — 경쟁 프레임워크에 없는 방법론적 엄밀성
2. **privilege 축의 직교성 논증**: principal grant(L1)와 credential(L7)의 분리가 confused deputy의 구조적 원인 — threat modeling의 경계 정의 수준으로 끌어올린 고유 프레이밍
3. **방향성→위협 성격** 원리 (저신뢰→고신뢰=오염, 역방향=노출)

### 치명적 약점
1. 관련연구 부재 — MAESTRO, 의료 8-boundary 논문, CLAWAUDIT 등 직접 경쟁자와의 비교가 원고에 없음
2. 실증 부재 — 6장 PoC에 LLM 호출이 없고(규칙 기반), TB-5/TB-6이 검증된 것처럼 서술됨 (soundness 문제)
3. "더 잘 표현한다"→"더 잘 찾는다" 사이의 논리적 도약이 실험 없이 전제됨
