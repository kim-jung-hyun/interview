## 기준선 — 모든 자료가 이것을 따른다

    기준 (AI GRC · 내 자리)  →  구현 (Development)  →  판정 (Assurance)  →  수용 (Risk / Business)

| 분리선 | 내용 |
|---|---|
| **①** | 만든 사람이 판정하지 않는다 (구현 ↔ Assurance) |
| **②** | 판정한 사람이 위험을 수용하지 않는다 (Assurance ↔ 수용) |
| **③** | **기준을 만든 사람이 그 기준으로 판정하지 않는다** (내 자리 ↔ Assurance) |

**Assurance = 실행 · 모니터링 · 시험 · 승인 · 감사.** Release Approver도 여기 있다.

> **"제 자리는 「기준 제공자」입니다. 저는 승인하지 않습니다 — 승인이 가능하도록 만듭니다. 제 산출물은 결정이 아니라 결정의 전제입니다."**

**「기준 제공자」** — 지원 직함이 `Staff AI Security Governance **Engineer**`다. 관리자가 아닌 개별 기여자(IC)이고 `Governance`는 기준을 세우는 일이다. **직함 자체가 이 포지셔닝의 근거다.**

내 산출물은 둘이다 — **① 개발팀용 기준·가이드**(규제 requirement → SW 구조), **② Assurance용 구조 요건**(assessment 가능한 evidence, audit 가능한 구조).

정본은 `manager/02_structure.md` §0, 근거는 `manager/06_ai_responsibility.md` §3, 그림은 `manager/figures/baseline.svg`.

### 이번 인터뷰의 경계

**구현 코드와 실험 수치는 꺼내지 않는다.** 넘기는 문장은 하나로 통일한다.

> **"구현 세부와 측정 결과는 기술 인터뷰에서 자세히 말씀드리겠습니다. 여기서는 구조만 말씀드리겠습니다."**

**수치는 말하지 않는다.** 건수·비율·F1·표본 수 전부 기술 인터뷰로 넘긴다. 물으면 **"확인했고 수치는 기술 인터뷰에서"**로 답한다.

**자기 PoC의 결함도 먼저 꺼내지 않는다.** 정책·가드레일 혼재 / fail-open / Scope 불일치는 **원칙으로** 말하고, 내 것의 실측은 물으면만 답한다 — **이 인터뷰의 평가 대상이 아니다.**

## 가장 강한 카드 3개

1. **기준선을 가장 먼저 깐다** (`02_structure.md` §0 · `figures/baseline.svg`) — 기준 → 구현 → 판정 → 수용과 분리선 3개. **역할 질문 전부가 이 한 장으로 답된다**
2. **탭4 승인 버튼 앞 대사** (`03_demo.md` §4) — 1.1·1.2·1.5와 maintain 질문을 한 번에 답한다
3. **역할 경계를 스스로 좁혀서 말한다** (`02_structure.md` §3) — **"저는 승인하지 않습니다. 승인이 가능하도록 만듭니다."** 실행·모니터링·감사·승인은 전부 Assurance이고 Release Approver도 내 자리가 아니다. 근거는 운영모델 표의 구조 — **AI GRC는 lifecycle 11단계 어디에서도 최종 책임 열에 나오지 않는다**

## 원칙으로 말하고, 내 것은 물으면만 답할 것 3개

**먼저 꺼내지 않는다.** 거버넌스 매니저 인터뷰의 평가 대상이 아니고, 구조 블록 시간을 자기 비판에 쓰게 된다. **기술 인터뷰에서 코드와 수치로 꺼낸다.**

| 원칙으로 말할 것 (MI) | 내 PoC 실측 (물으면만) | 위치 |
|---|---|---|
| 정책과 가드레일은 실무에서 거의 항상 섞인다. **도입 첫 단계에서 구별 기준을 세워야 한다** | 내 정책 파일이 섞여 있다 | `02_structure.md` §2 / Q3 |
| **통제 실패 시 기본 거동을 정책에서 선언해야 한다.** 선언이 없으면 통과 쪽으로 구현된다 | 내 구현은 fail-open이다 | §5 / Q4 |
| **Scope 선언과 그 Scope가 요구하는 통제를 갖추는 것은 다른 일이다** | Scope 3에 Scope 1 통제를 붙였다 | §5 / Q4 |

**물으면 숨기지 않는다.** 먼저 안 꺼내는 것과 부인하는 것은 다르다.

## 사실과 다르게 말하면 안 되는 것

인젝션 방어 성공(재현 안 됨, 음성 대조군) · 논문 게재(Major Revision) · 표준 수립(단일 파이프라인 baseline) · 프레임워크 자작(NIST·AWS·MS에서 가져옴) · 공식 NIST Profile(use-case Target Profile임) · PIPA 국외이전 예외 개수(확인 안 됨).
